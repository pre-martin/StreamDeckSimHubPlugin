# StreamDeckSimHub.Installer - Agent Guide

This document provides coding agents with essential information about building, testing, and maintaining this codebase.

## Project Overview

**StreamDeckSimHub.Installer** is a standalone Windows installer for the StreamDeckSimHub plugin. It is a WPF desktop app that executes a sequence of installation actions (runtime check, plugin installation, process control, and verification) and reports progress to the user.

The installer targets .NET Framework because it is included with Windows, so end users do not need to install additional software just to run the installer.

- **Language**: C# with CommunityToolkit.Mvvm
- **Framework**: .NET Framework 4.8 (WPF), SDK-style project
- **Architecture**: Action pipeline with MVVM-based UI
- **Packaging**: Single executable with embedded plugin payload and embedded NuGet dependencies (custom `AssemblyLoader` + `AppDomain.AssemblyResolve`, see `Tools/AssemblyLoader.cs`)
- **License**: LGPL-3.0-or-later

## Build Commands

### Prerequisites
- Windows
- .NET Framework 4.8 targeting pack
- .NET SDK (for the `dotnet` CLI)
- PowerShell (optional, for release automation in parent repo)

### Restore Dependencies
```bat
dotnet restore StreamDeckSimHub.Installer.csproj
```

### Build
```bat
# Build Debug
dotnet build StreamDeckSimHub.Installer.csproj -c Debug

# Build Release
dotnet build StreamDeckSimHub.Installer.csproj -c Release
```

For full release packaging (plugin + installer), use `deployInstaller.bat` in the repository root, which combines all required commands.

### Output
```bat
# Main binary
bin/Release/StreamDeckSimHub.Installer.exe

# Versioned copy generated by RenameInstaller target
bin/Release/StreamDeckSimHub.Installer-v<version>.exe
```

## Code Style Guidelines

### General
- Keep code simple and consistent with existing installer patterns.
- Prefer explicit, actionable log messages for installation steps.
- Handle errors defensively; installers must fail predictably.
- Remove unused imports.

### File Headers
- All C# files must include:
  ```csharp
  // Copyright (C) YEAR Martin Renner
  // LGPL-3.0-or-later (see file COPYING and COPYING.LESSER)
  ```
  where `YEAR` is the current year.

- When modifying an existing file, update the year in the header to the current year.

### Naming Conventions
- **Classes/Interfaces**: PascalCase
- **Methods/Properties**: PascalCase
- **Private fields**: `_camelCase`
- **Parameters/Locals**: camelCase
- Keep action names descriptive and user-facing (`Name`, `Message`).

### Async/Await
- Action execution is asynchronous (`Task<ActionResult>`).
- Keep UI responsive by running install work off the UI thread and marshaling UI updates through `Application.Current.Dispatcher`.
- Avoid long blocking work on the UI thread.

### Logging and Errors
- Use `NLog` for step-level progress and failure diagnostics.
- Include enough context in error logs to troubleshoot file/registry/process issues.
- Convert exceptions into `ActionResult.Error` in action boundaries instead of crashing the app.

## Project-Specific Patterns

### Installer Action Pattern
1. Derive action classes from `AbstractInstallerAction`.
2. Implement `ExecuteInternal()` and return `ActionResult`.
3. Use `SetAndLogInfo` / `SetAndLogError` to keep UI message and logs in sync.
4. Keep each action focused on one responsibility.

### Installation Flow
`MainWindowViewModel` runs actions in this order:
1. `CheckDotnetRuntime`
2. `StopStreamDeckSoftware`
3. `InstallStreamDeckPlugin`
4. `StartStreamDeckSoftware`
5. `VerifySimHubPlugin`

The final user status is computed from the highest-severity `ActionResult`.

### Configuration and Environment
- Centralize paths, registry keys, and required versions in `Tools/Configuration.cs`.
- Stream Deck plugin files are installed into `%AppData%\Elgato\StreamDeck\Plugins`.
- SimHub plugin compatibility is checked against `RequiredSimHubPluginVersion`.

## Common Pitfalls

1. **UI thread access**: Updating bound collections/properties from background threads will fail without dispatcher marshaling.
2. **File locks**: Existing plugin files may be locked if Stream Deck is still running.
3. **Resource packaging**: The plugin archive must be embedded with the expected name (`PluginZipName`).
4. **Registry assumptions**: Install locations may differ from defaults; always honor configured registry paths first.
5. **Framework mismatch**: This project targets .NET Framework 4.8, not the .NET 8 stack used by the main plugin.
6. **Embedded dependencies**: NuGet dependencies (and their transitive dependencies) are embedded via the `EmbedRuntimeDependencies` MSBuild target and resolved by `AssemblyLoader.Register()`, which must be called before any code touches a type from one of those dependencies (done in the `App` static constructor). Adding a new `PackageReference` does not require any extra step - it is picked up automatically.
